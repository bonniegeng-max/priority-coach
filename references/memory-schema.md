# 最小记忆 schema

本 skill 的记忆目标不是“替用户记住全部人生”，而是帮用户在下一次回来时，不必从零开始。

## 1. 推荐最小结构

```json
{
  "weekly_focus": [],
  "current_priority_pool": [],
  "avoid_now_pool": [],
  "today_min_action": "",
  "energy_pattern": "",
  "support_preference": ""
}
```

## 2. 字段说明

- `weekly_focus`
  - 本周最想守住的 1–3 条主线
  - 例如：`["自我修复", "工作安全感"]`

- `current_priority_pool`
  - 当前一轮会话里已经出现过的候选优先事项
  - 方便下次回来时快速承接

- `avoid_now_pool`
  - 明确先不碰、先不一起扛的事
  - 这类信息对减负很关键

- `today_min_action`
  - 今天已经定下来的最小动作
  - 例如：`"出门走 20 分钟"`

- `energy_pattern`
  - 最近更常见的状态
  - 例如：`"容易过载"`、`"开始困难"`、`"白天还行，晚上会散掉"`

- `support_preference`
  - 用户偏好的陪伴方式
  - 例如：`"少问开放题，先给选项"`、`"要温柔但直接"`

## 3. 保存规则

只有在用户明确同意时，才保存到本地记录。

推荐默认只保存：
- `weekly_focus`
- `current_priority_pool`
- `avoid_now_pool`
- `today_min_action`
- `energy_pattern`
- `support_preference`

默认不保存：
- 长篇原始回答
- 敏感情绪细节
- 明显涉及他人隐私的内容

如果确需保存 `rawAnswers`：
- 必须再次明确征得同意
- 并提醒用户可随时删除

## 4. 使用方式

### 下次回来时可这样承接
- “你上次更想守住的是自我修复和工作安全感，今天还成立吗？”
- “你最近连续几次都提到开始困难，要不要今天先保住一个 5 分钟版本？”
- “你上次明确说先不一起扛的是家务细节和额外新目标，今天还这么放吗？”

### 不要这样承接
- 不要直接搬出大量旧记录
- 不要制造“你上次说过，你怎么又没做到”的指责感
- 不要默认长期记忆一定正确，始终允许用户覆盖旧判断
