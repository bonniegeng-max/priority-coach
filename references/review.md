# 主线回顾与断更承接（`mainline_review`）

本状态回答长周期问题："我定的优先级还对不对"，以及"我停了一阵，怎么接上"。

> **记录铁律**：本文所有"记录动作"都受同一条规则约束——**必须先获得用户明确同意才写盘**。用户未同意、拒绝或未回应时，跳过记录动作，不产生任何文件。

## 何时进入本状态

仅由用户主动触发，不主动推销：

- **承接类**："我回来了""接着上次""我之前定过什么""上次聊到哪了"
- **回顾类**："我的主线变了吗""帮我回顾这周 / 这月""最近又乱了，对照一下之前定的"

## 模式 A · 断更承接（回来了）

目标：让用户**不从零开始**，也**不为中断付出羞辱成本**。

### 步骤

1. 先跑 `python3 scripts/record.py latest` 读最近一次完整结果卡
   - 若没有任何记录 → 直接进入 `cold_start`，不硬演承接
2. 用一句话接住中断，例如：
   > 你上次（{date}）收拢的三件事是 X / Y / Z。断了一阵很正常，先看看它们还成立吗。
3. 给三个轻选项：
   - **A 还成立** → 从三件事里挑今天先动哪一件 → 进入 `today_plan`
   - **B 部分变了** → 只换掉变的那件；可参考当时的候选列表，不重跑 5 问
   - **C 全变了 / 说不上来** → 进入一次轻量 `cold_start`（可用 3 问最小子集）
4. 无论选哪个，收尾说一句："回来接着，就是没断。"

### 禁止

- 不问"为什么停了""怎么这么久没来"
- 不把中断当成需要解释或道歉的事件
- 不用"连续天数""打卡中断"之类的表述

## 模式 B · 主线重检（周 / 月回顾）

目标：输出"稳 / 漂 / 下车"三栏判断，让用户看见主线的真实轨迹。

### 步骤

1. 跑 `python3 scripts/record.py list` 看有多少条记录
   - **不足 2 条** → 如实说明还攒不出对比，建议正常用几天再回来，不硬演回顾
2. 有 2 条以上：
   - 跑 `python3 scripts/record.py weekly-summary --days 7`（月度用 `--days 30`，或按用户指定周期）
   - 对比最近两次记录的 `topPriorities`
3. 输出**主线重检卡**：

```md
## 主线重检卡
- 稳住的主线：<连续出现、仍在推进的>
- 漂走的主线：<出现过但最近没再出现的>
- 建议下车：<明显不成立，或一直是"应该做"而非"想做"的>
- 下一句：<一条温和的调整建议>
```

### 判断规则

- 连续 2 次以上出现的优先事项 = **稳**
- 只出现过 1 次、且当时的最小行动也没做的 = 大概率**漂了**（表述为"先放一放"，不说"失败"）
- 用户口中的"应该"多于"想" = **下车候选**
- 记录之间间隔很久（如超过 3 周）= 提醒一句"样本间隔有点长，判断仅供参考"

### 结束

问一句："要按这个更新你当前的三件事吗？"——**用户同意后才写入**，否则只输出卡片。

## 回顾话术

优先用：
- "先看看这条线还在不在"
- "稳住的不用动，漂了的我们再选一次"
- "先放一放，不等于失败"
- "回来接着，就是没断"

禁止：
- "你上次没做到""为什么没坚持"
- 任何打卡式审判、连续天数羞辱、与其他用户比较

## 记录动作（需用户同意）

- 回顾后若用户明确说"更新一下 / 记下来"：
  ```bash
  python3 scripts/record.py add --data '{"date":"…","state":"…","topPriorities":["…"],"smallestActionToday":"…","notNow":["…"]}'
  ```
  旧记录**保留不覆盖**，形成主线轨迹，供下次回顾对比。
- 会话摘要同样需同意后写入：`enteredState=mainline_review`、`endedState=`（实际去向）、`resultType=priority_card`。
- 用户未同意时，两层都不写。
